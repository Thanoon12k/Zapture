TRUST THE METHOD, NOT A SLOGAN

What we tested.
What remains unknown.

Repeatable conditions

  • 3 resolutions × 3 workloads.
  • 4 screenshot tools + 2 recording paths.
  • 3 repetitions = 162 runs across 54 scenarios.
  • Seeded, shuffled app/trial order inside each group.
  • 2-second warmup + 8-second recording measurement.
  • Same target H.264 settings: x264 ultrafast, CRF 23, 30 fps, audio off.

Validation, not just file creation

Every screenshot was decoded and checked for dimensions and visible content. Videos were frame-counted and a sample frame decoded. Raw data retains errors. These checks catch obvious failures but do not prove perfect motion, latency or frame delivery.

Earlier checks also covered five repeated start/stop cycles and a two-minute recording. Those are separate from this 162-run matrix.

Cloud hardware limits

Virtual X11 on a Debian 13 cloud container, with software rendering and no GPU device. Nine logical CPUs and about 10.45 GiB of memory were visible, which does not establish reserved cloud capacity.

No Windows, macOS, hardware audio, GPU, battery, thermal, gaming or multi-hour stability results are claimed.

Competitor scope

FFmpeg is a recording baseline, not a full GUI replacement. ImageMagick and scrot are screenshot command-line tools. Zapture measurements include its resident UI and recorder children; baseline measurements exclude the idle Zapture UI.

OBS produced black output in the earlier cloud attempt. Its runtime measurements are excluded. ShareX and Greenshot appear only in the download-size comparison.
